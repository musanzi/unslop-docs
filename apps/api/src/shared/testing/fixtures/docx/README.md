# DOCX upload fixtures

These synthetic documents contain no student data. The accepted structure fixtures use WordprocessingML packages with styles, numbering, relationships, media, notes, comments, headers, and footers. They are suitable for upload checks. The rejection fixtures deliberately contain unsupported or damaged content.

| Files                                                                                                         | Expected result                                                                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `english-structures.docx`, `french-structures.docx`, `mixed-structures.docx`                                  | Accepted. Headings, paragraphs, numbered lists, tables, bold and italic runs, hyperlinks, an image, an equation, a reference field, and protected ancillary parts.                   |
| `english-content-controls.docx`, `french-content-controls.docx`                                               | Accepted. Inline, block, nested, row-level, and cell-level content controls read as their visible text; the revised main part contains no `w:sdt` wrappers.                          |
| `header-content-controls.docx`                                                                                | Accepted. A content control in the header and a tracked insertion in a footnote stay byte for byte in those preserved parts.                                                         |
| `tracked-changes-final-version.docx`                                                                          | Accepted as the final version: insertions and the inserted row are kept, deletions and the deleted row are dropped, moved text appears once, and property-change history is removed. |
| `content-control.docx`, `tracked-changes.docx`, `text-box.docx`                                               | Accepted. These files were rejected before issue #15; their bytes are unchanged. The text box is a protected `text-box` element whose visible words count toward the limit.          |
| `short-uncertain.docx`                                                                                        | Accepted without a confident language classification.                                                                                                                                |
| `exactly-10000-words.docx`                                                                                    | Reader accepts the former word-limit boundary. Upload acceptance also requires five rendered pages or fewer.                                                                         |
| `over-10000-words.docx`, `controls-over-10000-words.docx`                                                     | Reader accepts both with a word count of 10,001. The second file splits words between a content control and a plain paragraph. Uploads have a separate page limit.                   |
| `embedded-object.docx`                                                                                        | Rejected with the unsupported structure named.                                                                                                                                       |
| `unsupported-spanish.docx`, `unsupported-german.docx`, `unsupported-russian.docx`, `unsupported-chinese.docx` | Rejected with the supported languages stated.                                                                                                                                        |
| `encrypted-zip.docx`, `encrypted-office-signature.docx`                                                       | Rejected with password-removal guidance. These test an encryption flag and an Office compound-file signature, respectively. They are not complete encrypted Office documents.        |
| `corrupt.docx`                                                                                                | Rejected as damaged.                                                                                                                                                                 |
| `zip-bomb.docx`                                                                                               | Rejected before expanding a 20,000,001-byte entry.                                                                                                                                   |

Regenerate all 23 files from the repository root:

```sh
node tools/generate-docx-fixtures.cjs
```

The generator uses `docx-fixture-catalog.ts`, `docx-reader-fixture.ts`, `docx-language-fixtures.ts`, and `revision-passages.ts`. ZIP timestamps are fixed. The reader specs load the committed files and verify their outcomes. Additional generated cases exercise corrupt CRCs, traversal, XML nesting and node limits, compressed expansion, formatting changes, mixed text runs, UTF-16, CDATA, nested tables, complex fields, preserved-byte isolation, co-authoring conflict markup, and passages kept after a failed preservation check. The revision specs also run the accepted content-control, header, tracked-change, and text-box fixtures through the editing workflow.

To capture evidence on the integration stack, sign in, open `/user/documents`, upload `content-control.docx` or `tracked-changes-final-version.docx`, and confirm that the upload is accepted and that both the original and the revised DOCX can be downloaded. Browser screenshot evidence must come from a stack running this revision. `node tools/generate-revision-fixtures.cjs <directory>` writes original and revised pairs with their notices for review; [docs/evidence/issue-15](../../../../../../docs/evidence/issue-15/README.md) holds the committed set.
