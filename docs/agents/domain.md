# Domain documentation

The frontend and API share one domain glossary and one ADR directory.

## Read before exploring

Read the root `GLOSSARY.md` and relevant decisions in `docs/adr/`.
If these files do not exist, continue without them.

## Use shared terms

Use the glossary's terms in code discussions, issues, and documentation.
When a term needs clarification, resolve its meaning before adding it.
Keep implementation details out of the glossary.

## Record decisions

Create glossary entries as terms are settled.
Record an ADR when a decision has meaningful reversal costs,
needs context, and reflects a real trade-off.

If a proposed change conflicts with an ADR, identify the conflict explicitly.
